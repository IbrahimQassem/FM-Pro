Blocking issues

  1. Privacy — manifests serialize personal search text. web_admin/lib/export-pages.ts:31 assigns raw state.identity to downloaded queryFingerprint. The actual UI identity at admin-app.tsx:1752 contains free-text search. exportCurrentPage repeats the raw identity at line1878. A name/email/phone searched by an administrator is therefore copied into downloadable JSON, contrary to the no-personal-data manifest requirement. Independently executed the actual export helper using a synthetic email identity and asserted that serialized output exclude it; this failed with ERR_ASSERTION: Export manifest must not retain raw personal search text. Replace exported identity with a deterministic opaque one-way digest; retain raw matching identity only in private in-memory state. Cover both full and current-page manifests with permanent pre-fix regression evidence. The initial reviewer probe used an incorrect relative import and produced module-not-found; that attempt is excluded and provides no RED credit. The corrected probe executed successfully before its intended business assertion failed.
  1. Correctness — cached snapshots mint traversal cursors. ResourcePage's snapshot callback always derives last and more from the first50/51 cached documents before setting cached. The Next control at admin-app.tsx:1290 checks only loading/more/last, and its handler likewise ignores cached state. A cache-only/incomplete snapshot can therefore authorize next-page traversal from its last cached row and skip records that were never server-validated. Cache-first display is allowed; server continuation must not originate from cache. Require an actual-component regression for cache-only51 rows, server transition and later offline/cache transitions, plus guarded handlers so stale callbacks cannot advance traversal even before React repaint. Preserve existing successful content and disclose offline state.
  1. Mandatory actual emulator gate failed. Parent log evidence/WO-03/B11-emulator-green.log currently reports 41 tests,38 passed,3 failed,0 skipped. Both roots' R06 record2001 continuation child cases throw Invalid query. Expected a string for document ID in startAfter(), but got a object; the parent case fails consequently. This is an SDK integration failure, not valid behavioral RED or GREEN. Determine the actual DocumentReference/document-ID boundary or SDK instance cause, correct it without weakening reachability assertions, and rerun the full affected actual gate. The coordinator owns this investigation/runtime.
