## Mid-flight legal writer versus pause: deterministic ordering

The existing 91-case suite proves only refusal against an already paused root. Add both orderings for representative real legal writers and verify all relevant attachment points: episode creator (RSS/save/import/preview/seed), moderation/count authority, manual review/account deletion, count/status maintenance. Reuse real callable/handler entry points and registered fixture ownership. Coordinate any required additional fixture path before edits. Source inspection/unit coverage may justify shared helper reuse, but do not claim an unexecuted writer's native race was tested.

1. **Writer commits before pause.** An observer around the actual writer SDK transaction reports that the root fence was read, then waits on a controller release signal. The controller DISPATCHES a real pause transaction without waiting for its completion, then releases the writer. The callback must never await that competing transaction. Await both only outside the transaction. Pessimistic locking is expected to serialize the writer before pause; assert native writer receipt/episode updateTime precedes pause commit, and the paused inventory includes exactly that committed result. A safe retry/refusal is also acceptable if the SDK chooses another legal ordering, but classify and assert the actual versions/outcome. No sleep or assumed callback order substitutes native evidence.
2. **Pause commits before writer's guarded read.** Start the actual writer invocation, gate immediately before its guarded SDK transaction/read without holding a Firestore lock, commit the genuine pause, then release the writer. It must observe pause and refuse without canonical/private partial writes. This is mid-invocation refusal, not a claim of a server transaction conflict. Exact pause version and unchanged canonical versions prove the ordering.
3. **Conflict/retry when actually observed.** Record native callback attempts and maxAttempts. Assert an unsuccessful attempt has no committed cursor; retry sees fresh fence/source and either legally serializes or refuses. Do not force optimistic conflict semantics onto the emulator's pessimistic transaction mode or require a retry when legal lock serialization occurs.

A test adapter may observe/gate the supplied SDK transaction while executing all actual SDK reads/writes; it must not implement fence decisions/arithmetic or alter return values. Core producer helpers already accept an SDK object, but the reconciliation tool's private factory identity must remain intact. Do not wrap its trusted facade or introduce a test-only production flag. Any additional instrumentation capability needs author proposal plus independent acceptance first.
