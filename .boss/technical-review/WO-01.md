## 1. Overview and impact

### 1.1 Proposed design — not implemented

- **Proposed new Firestore path:** `{root}/stationPrivate/stations/{stationId}`, for both `HudHudDev` and `HudHudOfficial`, using the station ID and server-owned schema/revision metadata.
- Private field set: `owner,address,contactPerson,contactPhone,contactEmail,streamType,audioCodec,bitrateKbps,sampleRateHz,transmitterPower,transmitterLocation,coverageArea,rds`, matching the current contract. Public social links and `streamUrl/backupStreamUrl` remain public because playback requires them.
- Guest, listener, station_admin and moderator cannot get/list/write private metadata, even for an assigned station. Super User may read; **all writes remain server-only**, including for super-admin clients.
- Save reads public/private documents and expected revisions, partitions fields, and writes both in one transaction. Distinguish explicit field deletion from omission by an older client. Missing private payload must not erase existing metadata.
- A compatible server can accept an authorized older mixed payload and split it safely. Quiesce or upgrade every direct administrative writer before cleanup; none may recreate private keys in public documents.
- Listener profile email is neither persisted nor used for admin display/search/name fallback. Admin user management uses UID/name. Any new feature exposing another user's Auth email requires a separate explicit privacy decision, not an implicit replacement endpoint.
- Do not delete Auth users, change login emails/password behavior, or remove email from the separately authorized private expiring verification challenge. Administrative actorEmail audit policy is outside this listener-profile cleanup; record a separate policy issue if wider scope is required.
