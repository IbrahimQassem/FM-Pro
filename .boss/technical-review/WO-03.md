## 1. Scope and agreed behavior to establish

### 1.1 Page, search, count and export contract

1. **Episodes:** filter server-side by stationId and `isPublished == true`, plus programId on a program page. Stable order: `broadcastAt DESC, priority DESC, documentId ASC`. T01 must explicitly document public-web tie-order changing from title to this tuple; Flutter priority tie semantics remain. Missing ordering fields are addressed in section1.3 before activation.
2. **Programs:** bounded independent active-program pages. Preserve featured/priority ordering only after checking all required fields and indexes, with document ID as tie-breaker. T01 must settle this before implementation; do not claim global ordering by sorting a partial page locally.
3. **Page size:**50 episodes or programs/request. One page request/user action; no automatic unbounded loop skipping drafts/invalid mappings. Cursor advances from the last raw document even when mapping rejects it. An empty mapped page with a cursor is not end-of-data. One lookahead document is permitted, making the return budget51.
4. **State:** initialLoading/ready/loadingMore/offline/error. A later-page error preserves existing content. Deduplicate IDs. Station/program/filter changes or refresh invalidate cursors and stale completions. Domain must not expose Firebase snapshots: use an opaque value cursor with version, root, station/program, filter fingerprint and sort tuple; reject cross-scope reuse.
5. **Deep links:** fetch the target episode directly, then validate its parent program/station, root, publication/deletion state and canonical IDs. Do not scan pages until episode10000. No autoplay. Foreign/draft targets show unavailable. A partial station page is not proof a program has no episodes.
6. **Admin pages:** server pages50 for non-report resources too; preserve collection-group root bounds before limit. Global sort must be expressed in supported queries. An old sorting option requiring absent fields/indexes must receive an explicit contract decision, not a misleading local sort.
7. **Admin text search:** Firestore has no arbitrary full-text contains query. Preserve the existing match predicate through two explicit modes: clearly labeled current-page search, and user-started resumable full-dataset scanning. Full scanning reads at most200 documents/continuation, displays “N examined, M matched so far,” supports continue/cancel, and never calls M a complete total before exhaustion. It can reach record2001/10000 without loading all records at once. Freeze filter/sort fingerprint and invalidate changed searches. T01 is the decision gate for this UX; if not accepted, record the alternative and new write set before dispatch. Do not silently substitute page search for global search acceptance.
8. **Counts:** server-filter total excludes unindexed free-text search; show asOf and distinguish matched-so-far. R07 proposes callable `adminGetUserCount`, returning only `{root,total,asOf}`. It accepts verified, authorized super_admin/station_admin/moderator identities using the existing authority convention and root allowlist. A listener, document owner or other user cannot obtain administrative statistics. The allowed root-level total exposes no IDs, email, documents or personal breakdowns.
9. **Exports:** “Export current page” exports exactly that page. “Export all matching results” performs an independent bounded cursor scan with frozen filters, start time, cancel/resume and progress. Write parts of at most1000 records each; fetch at most200/request; do not retain a10000-row array. Manifest identifies scope, counts and completeness. This is not a transactionally fixed snapshot under concurrent writes; disclose that and test complete equality on a fixed fixture. Use WO-01-authorized projections, never confidential fields unavailable to the actor.
