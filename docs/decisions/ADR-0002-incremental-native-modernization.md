# ADR-0002: Incremental native modernization

الحالة: accepted  
التاريخ: 2026-08-26

## السياق

التطبيق Android أصلي يعمل في الإنتاج ويحتوي ثلاث نكهات واعتمادًا كبيرًا على
Firebase وخدمات صوت legacy. إعادة الكتابة الكاملة تطيل فترة وجود تنفيذين وتخفي
انحراف السلوك والبيانات.

## القرار

يبقى التطبيق Android أصليًا ويحدث بشرائح رأسية. يبدأ الفصل داخل `:app`، ويستخدم
Kotlin وJetpack للكود الجديد، مع adapters مؤقتة فقط عند الحدود. Material 3 Views
هو خط الأساس، وCompose أو multi-module يحتاجان ADR بعد تجربة مقاسة.

## البدائل

- إعادة كتابة كاملة: مرفوضة بسبب مخاطر parity والإطلاق والبيانات.
- تجميل XML دون فصل: مرفوض لأنه يبقي Firebase والمشغل مقترنين بالواجهات.
- تقسيم وحدات Gradle فورًا: مؤجل حتى تثبت الحدود داخل الحزم.

## النتائج

- كل مرحلة تبقى قابلة للبناء والإطلاق.
- سرعة البداية أقل من rewrite، لكن إزالة legacy مستمرة وقابلة للقياس.
- أي مسار مزدوج مؤقت يسجل في سجل الدين ويحذف ضمن موعد واضح.
