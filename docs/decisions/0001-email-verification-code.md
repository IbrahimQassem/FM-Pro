# ADR-0001 — توثيق البريد برمز رقمي

- الحالة: معتمد
- التاريخ: 2026-09-02

## القرار

يعتمد HudHud FM رمزًا رقميًا أحادي الاستخدام من ستة أرقام داخل التطبيق بدل
رابط Firebase. يولد Cloud Functions الرمز ويرسل الرسالة عبر Resend؛ لا يولد
Flutter الرمز ولا يقرأ مستند التحدي.

## الضوابط

- يخزن HMAC-SHA-256 للرمز مرتبطًا بـUID مع pepper سري، لا الرمز الصريح.
- تنتهي صلاحية الرمز بعد 10 دقائق، وتتاح إعادة الإرسال بعد 60 ثانية، بحد خمسة
  إرسالات في الساعة وخمس محاولات لكل رمز.
- يحدّث الخادم `emailVerified` وينشئ ملف المستمع canonical بعد نجاح التحقق.
- تمنع Rules الحساب غير الموثق من UGC والمفضلة والاشتراكات.
- تحذف مهمة يومية الحساب غير الموثق بعد 30 يومًا فقط إذا كان له challenge قديم
  ولا يملك ملف مستمع.
- تحفظ إعدادات Resend والـpepper في Firebase Secret Manager ولا تدخل Git أو logs.

## البدائل والنتائج

رابط Firebase أبسط تشغيليًا، لكنه لا يحقق تجربة إدخال الرمز المطلوبة. اختيار
الرمز يضيف اعتمادًا على مزود بريد وCloud Functions ومراقبة للتسليم، مقابل رحلة
موحدة داخل التطبيق. لا يشغّل المساران معًا لتجنب حالات توثيق متعارضة.

الرجوع الآمن هو إيقاف واجهة طلب الرمز قبل تخفيف Rules أو طرح رابط التحقق؛ يجب
تنسيق تطبيق العميل وFunctions وRules في إصدار واحد.
