# Signing-key incident and rotation plan

الحالة: التنفيذ المحلي مكتمل؛ التدوير الخارجي وتنظيف التاريخ معلقان
بند الدين: TD-002

## ما نُفذ محليًا

- إزالة `key.properties` من التتبع الحالي مع إبقاء النسخة المحلية للمطور.
- حظر الملف وملفات keystore في `.gitignore`.
- إضافة `key.properties.example` بلا قيم حقيقية.
- جعل debug configuration قابلة للتقييم دون signing properties.

## ما يتطلب مالك الإصدار

1. اعتبر القيم التاريخية مكشوفة وحدد هل المفتاح مسجل في Play App Signing.
2. أنشئ أو اطلب مفتاح upload جديدًا وفق آلية متجر النشر المعتمدة.
3. خزّن القيم الجديدة في secret store وCI، وليس في ملفات مشتركة.
4. تحقق من توقيع build تجريبي ومن إمكانية التحديث فوق آخر إصدار.
5. ألغِ المفتاح أو بيانات الاعتماد القديمة حيث تسمح الجهة المالكة.
6. بعد تنسيق كل المستنسخات والفروع، قرر هل يلزم تنظيف تاريخ Git. هذه عملية
   تعيد كتابة التاريخ ولا تُنفذ دون موافقة صريحة وخطة استعادة.

## معيار الإغلاق

يغلق TD-002 فقط بعد إثبات تدوير بيانات الاعتماد، نجاح إصدار موقّع بالمفتاح
المعتمد، وعدم وجود السر في الفروع أو artifacts المتداولة.
